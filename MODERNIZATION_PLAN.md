# План модернизации Payroll

## Цель

Постепенно привести приложение к более надежной архитектуре без резкой переписки всего проекта. Каждый этап должен оставлять проект собираемым.

## Этап 1. Базовая устойчивость

- Привести `CMakeLists.txt` к одному стандарту C++ и убрать принудительный `Debug`.
- Добавить базовые проверки ошибок при запуске GLFW и создании окна.
- Включить `PRAGMA foreign_keys = ON` при открытии SQLite-базы.
- Настроить разумный `busy_timeout` для SQLite.
- Проверять сборку после изменений.

## Этап 2. Слой базы данных

- Добавить в `Database` вспомогательные методы для prepared statements.
- Перевести операции записи с конкатенации SQL-строк на bind-параметры.
- Добавить транзакции для составных операций: очистка, создание базы, удаление связанных данных.
- Централизовать сообщения об ошибках БД.

## Этап 3. Версионирование схемы

- Ввести версию схемы через `PRAGMA user_version`.
- Добавить миграции для обновления старых `.db`.
- Исправить повторную вставку строки `Settings` при создании/инициализации базы.

## Этап 4. Упрощение панелей

- Выделить повторяющиеся CRUD-паттерны справочников.
- Оставить в панелях UI-логику, а SQL перенести в отдельные функции/репозитории.
- Начать с простой панели, например `DivisionsPanel`, затем перенести подход на остальные.

## Этап 5. UX и отчеты

- Добавить понятные подтверждения удаления и сообщения о причинах отказа.
- Улучшить поиск, сортировку и отображение статуса открытой базы.
- Доработать HTML-отчеты: выбор пути, печатные стили, обработка ошибок.

## Этап 6. Проверки

- Добавить минимальные тесты для расчетов и миграций БД.
- Добавить smoke-сценарий создания тестовой базы.
- Включить предупреждения компилятора для собственного кода.

## Решение по зависимостям

- Не использовать libharu: отчеты формировать в HTML.
- Не использовать nlohmann/json: настройки хранить в простом текстовом файле.
- Для ImGui, ImGuiFileDialog, GLFW и SQLite использовать локальный `thirdparty`, а при его отсутствии скачивать зависимости через `FetchContent`.
